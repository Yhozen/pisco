title: Desire: the first third-party Direct3D 12 game
prs: PRs #28–#34
---
Desire (DESI:Re v0.1), a free maze escape on its author's own Direct3D 12 engine, on the Windows x64 runtime.
Played by hand in Chrome on an M1 MacBook Pro: the logo, the maze, the enemy, the CRT effect, GAME OVER.

- **Checked against Wine:** the calls up to the main loop are Wine's (77 steps); given the seeds a Wine run's
  `std::random_device` drew, the maze the game writes is Wine's byte for byte (3 of 3 runs); the window title at
  each checkpoint and the set of Direct3D 12 methods called (51) are Wine's. In headless Chrome the still screens are
  within 0.3 of 255 of Wine's screenshots.
- **`pisco build`** reads a zip, adds your own files beside the exe (here Microsoft's C++ runtime DLLs), and
  compiles the title's HLSL into the image.
- **The recompiler** reads MSVC's current FH4 exception tables (a missing texture is thrown, caught and shown as under
  Wine) and its two-level `switch` tables (78 recovered in Desire's images instead of 43).
- **The Windows x64 runtime** gets a real window and message queue, the keyboard and the virtual clock (shared with the
  x86 runtime), WIC's PNG decoding (stb_image), and the D3D12 Memory Allocator's calls.
- **The WebGPU back end** merges each buffer's uploads and reuses bind groups: a profile of the first hand play showed
  48 MB uploaded a frame; Desire went from 18–21 to about 38 frames a second.
