PISCO

PISCO Imitates Systems, Compiles Originals. It runs x86 titles in WebAssembly, in a browser tab or in Node, by recompiling their code ahead of time and supplying the system they were written for: one recompiler, one package format (pisco build makes a title image from a recipe and your own copy of the title), and several compatibility runtimes. Nothing of a title is in the repository. Windows titles are checked against Wine, screen by screen and call by call.

Source: github.com/Yhozen/pisco · Progress map: what each runtime implements against what titles use · Videos: releases

Changelog

Desire: the first third-party Direct3D 12 game 2026-11-27in review: PRs #28–#34

Desire (DESI:Re v0.1), a free maze escape on its author's own Direct3D 12 engine, on the Windows x64 runtime. Played by hand in Chrome on an M1 MacBook Pro: the logo, the maze, the enemy, the CRT effect, GAME OVER.

  • Checked against Wine: the calls up to the main loop are Wine's (77 steps); given the seeds a Wine run's std::random_device drew, the maze the game writes is Wine's byte for byte (3 of 3 runs); the window title at each checkpoint and the set of Direct3D 12 methods called (51) are Wine's. In headless Chrome the still screens are within 0.3 of 255 of Wine's screenshots.
  • pisco build reads a zip, adds your own files beside the exe (here Microsoft's C++ runtime DLLs), and compiles the title's HLSL into the image.
  • The recompiler reads MSVC's current FH4 exception tables (a missing texture is thrown, caught and shown as under Wine) and its two-level switch tables (78 recovered in Desire's images instead of 43).
  • The Windows x64 runtime gets a real window and message queue, the keyboard and the virtual clock (shared with the x86 runtime), WIC's PNG decoding (stb_image), and the D3D12 Memory Allocator's calls.
  • The WebGPU back end merges each buffer's uploads and reuses bind groups: a profile of the first hand play showed 48 MB uploaded a frame; Desire went from 18–21 to about 38 frames a second.

neofetch: Linux processes 2026-11-26PR #35

neofetch 7.1.0, a bash script, runs on bash and busybox built as static Linux programs: 83 processes forked and executed (fork, execve, wait4, pipes), each in a worker with memory of its own. A title image can now hold several programs.

A fourth runtime: Linux x64, with fastfetch 2026-11-26PR #31

Linux at its system calls, for one statically linked program: files, memory, the clock, a generated /proc. The recompiler reads ELF; the core's system-neutral parts moved to files of their own. fastfetch 2.71.0 prints the machine it finds, a Linux x86-64 system imitated in WebAssembly, with its logo and colours, in Node and in the page.

Tag in the browser, faster 2026-11-26PRs #26, #27

  • Tag: The Power of Paint was played by hand through level 3. A Chrome profile showed its thread waiting on 21,000 file checks to the server and its whole 384 KiB vertex buffer re-sent a dozen times a frame; file checks are now answered once and only the changed bytes are sent (50 GB to 1.1 GB over a session).
  • Windows x64 titles get a window again; the docs say where every runtime stands, and what to do if the browser ever becomes the limit.

Tag: The Power of Paint, a Direct3D 9 shader game 2026-11-25PRs #18–#24

DigiPen's paint-gun game (2008), with Microsoft's own D3DX from its installer lifted beside it: its 16 effects compile at run time to the same 46 shaders as under Wine, Direct3D 9 shader bytecode is translated to WGSL, FMOD Ex's calls are Wine's, and in headless Chrome its first level is within 1.4 of 255 of Wine's screenshots on average.

PISCO: runtimes as peers 2026-11-25PRs #11–#17

  • The project is renamed PISCO, with its logo.
  • A folder and a base per runtime (Xbox Series, Windows x64, Windows x86), one list of each runtime's files, recipes for every base; the 32-bit side of the shared runtime made right.
  • CI for the tests that need no game files, and reuse lint.

Microsoft's desktop D3D12 samples 2026-11-25

Steps 1 and 2 of the graphics ladder: Microsoft's SimpleTriangleDesktop (clang-cl and MSVC builds) and SimplePBR on the Windows x64 runtime, drawn with WebGPU.

Narbacular Drop, a 2005 Windows PC game 2026-11-25PRs #1–#10

The first Windows PC title, a 32-bit Direct3D 9 game, played by hand in Chrome on an M1 MacBook Pro (video). What it took: the recompiler's 32-bit mode with x87, a Win32 process for a 32-bit guest, fixed-function Direct3D 9 on WebGPU, GDI text, FMOD 3 on an AudioWorklet, DirectInput from the keyboard and a Pointer Lock mouse, saves in OPFS, and recipes that build title images. 103–355 frames a second on that machine.

XCL's console checks, 50 of 50 2026-11-24

Step 4 of the ladder: XCL's console test title passes all 50 of its checks in Chrome. The progress map shows what the runtime implements against what titles use.

Doom as an Xbox console title, in a web browser 2026-11-24

doomgeneric + Freedoom, built against D3D12.X, GameInput, XAudio2 and XGameSave; its x86-64 code recompiled to WebAssembly, D3D12.X translated to WebGPU, XAudio2 mixed into an AudioWorklet, saves kept in the browser (OPFS). Recorded in headless Chrome with WebGPU on SwiftShader (no GPU); every frame was read back from WebGPU. Shows: title and attract demo, a new game from scripted keys, the automap, a save, a page reload (a new title process), the save loaded back.
